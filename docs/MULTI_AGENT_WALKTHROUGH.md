# 这次 Multi-Agent 协作怎样完成

## 先统一接口，再并行开发

主 Agent 先完成 PRD、数据库与 API 设计，用户确认后才启动开发。前端、后端、QA 读取同一份契约，所以金额始终是两位小数字符串，类型始终是 income / expense，列表和 summary 使用同名筛选参数。

三个原生子 Agent 各有文件边界：前端只改 frontend，后端只改 backend，QA 只改 tests、QA 报告与截图。主 Agent 管理契约、SQL、集成、进程与根文档。没有额外项目经理，没有嵌套创建后代，也没有安装 Codex CLI 或其他多 Agent 框架。

角色定义在 `.codex/agents/`，派发时明确传入职责和规则，不假定配置自动热加载。P0 未通过前不安排 P1；数据库缺失时先完成离线工作，如实记录跳过项，部署后再验证真实数据库。

## 代码从哪里开始读

| 位置 | 核心逻辑 |
| --- | --- |
| [TransactionForm.vue](../frontend/src/components/TransactionForm.vue) | 表单校验、编辑回填与取消，只提交五个可写字段 |
| [ledger.js](../frontend/src/composables/ledger.js) | 列表和统计整体替换，请求版本防旧响应，提交锁防重复请求 |
| [money.js](../frontend/src/utils/money.js) | 用字符串把 12.3 补成 12.30，不先转浮点再舍入 |
| [chart.js](../frontend/src/utils/chart.js) | 图形几何使用近似 Number，金额展示保持原始文本 |
| [schemas.py](../backend/app/schemas.py) | 后端再次校验金额、日期、类型、长度和未知字段，金额转 Decimal |
| [crud.py](../backend/app/crud.py) | 精确聚合，新增、编辑和删除提交事务后才返回成功 |
| [database.py](../backend/app/database.py) | 每请求独立 Session，失败回滚并关闭，只设置连接会话属性 |

页面点击保存后，数据依次经过表单、Axios、FastAPI 校验、SQLAlchemy 事务，最终写入 MySQL。刷新页面时重新查询 MySQL，Vue 内存状态和浏览器缓存都不是持久化来源。

## Bug 处理如何分工

- 主 Agent 发现写入 5xx 不能证明一定未提交，分派前端增加结果未确认保护；QA 独立检查函数和真实 503 页面，没有冒充已执行完整的“提交后回执丢失”数据库故障注入。
- QA 看真实手机截图发现金额拆行、备注竖排，主 Agent 分派前端修 CSS，再由 QA 增加行数、列宽及内部滚动检查。页面不溢出并不自动表示内容可读。
- 前端开发者发现全局 SVG 图标样式压缩环图，修正后 QA 检查实际图形路径尺寸，而不只判断 SVG 元素存在。
- 后端开发者修正更新时间与 ORM 默认值的交互，QA 在真实 MySQL 测试记录中设置未来时间，确认编辑不会令时间倒退。
- QA 把空查询结果 `()` 当作 `[]` 比较，修复仅在测试目录进行，没有为工具问题盲改业务代码。保护基线也改为动态初始记录快照，不依赖固定演示 ID。

每个问题记录来源、根因、修复人和复测证据；开发者自查发现的问题不会写成 QA 先前独立发现。
