# 个人记账 Demo 产品需求

版本：0.1，状态：用户已于 2026-11-16 确认，进入第三阶段。以下功能作为开发与验收基线，不代表已实现。

## 目标与使用场景

面向单个本机用户记录人民币收入与支出，直观看到记录和结余。通过这个小项目体验主 Agent 统一规划、三个原生子 Agent 按职责开发、真实联调和缺陷复测的过程。

## 功能优先级

| 优先级 | 功能 | 验收标准 |
| --- | --- | --- |
| P0 | 添加记录 | 输入正金额、类型、分类、记账日期和可选备注；成功写入 MySQL 后才提示成功 |
| P0 | 全部记录 | 首次打开及刷新时从 API 获取全部记录；日期倒序，同日按 ID 倒序；不使用本地存储代替数据库 |
| P0 | 三项统计 | 展示总收入、总支出、结余；结余允许为负；空数据均显示 `0.00` |
| P0 | 输入校验 | 拒绝零、负数、超额金额、超过两位小数、非法类型和缺少必填字段；后端独立校验 |
| P0 | 持久化 | 页面新增收入和支出，SQL 查询可见；刷新后记录和统计不变 |
| P0 | 页面状态 | 有加载、空记录、校验错误、请求失败和提交中状态；数据库失败不显示“保存成功” |
| P1 | 编辑与删除 | 编辑回填后保存；删除前确认；成功后重新加载列表与统计；不存在的 ID 返回 404 |
| P1 | 筛选 | 按类型、分类、起止日期筛选；条件为 AND；统计和列表使用相同条件；可一键清空 |
| P1 | 简单图表 | ECharts 支出分类占比图，数据来自 summary；与当前筛选一致；无支出时展示空状态 |

P0 先完成并验证，再进入 P1；为避免后续改字段，P1 接口一并纳入待确认契约。暂不实现分类独立增删改后台，只提供分类输入、推荐分类和分类筛选。

## 页面与交互

单页中文界面。2026-11-17 按用户提供的参考图调整为灰绿侧栏、白底细边框的收支概览：顶部标题、三项统计和筛选；中部左侧结余走势、右侧支出分类；下方左侧收支明细、右侧记账表单。侧栏定位概览、明细、分析和记账区。窄屏导航横排，内容按顺序堆叠，明细仅在表格容器内横向滚动。金额同时标明收入 / 支出，不仅靠颜色区分。

结余走势直接使用当前完整列表快照，按记账日期升序分组，将收入减支出从 0 累计；与列表、统计和分类图使用同一筛选范围。精确计算保留整数分，图表几何数值允许转 Number，提示和可展开的走势数据保留精确金额。空范围展示空状态，不补造记录或账户初始余额。接口、数据库和写入流程沿用现有契约。

表单字段：金额、类型（默认支出）、分类、记账日期（默认 Asia/Shanghai 当天）、备注。金额允许用户输入 `12`、`12.3`，前端在验证后按十进制文本规则转为 `12.00`、`12.30`；超过两位小数直接提示，不静默四舍五入。API 仅接受固定两位小数字符串。

分类可自由输入，去除首尾空白后长度为 1～50 字符。建议收入分类：工资、奖金、兼职、理财、其他；支出分类：餐饮、交通、购物、居住、医疗、娱乐、其他。推荐值不构成后端枚举，不限制新增分类。

提交期间禁用重复提交。编辑取消不改变数据。删除取消不发请求。写操作成功后重新请求当前筛选下的列表和统计，不把前端临时数据当作已落库结果。若新记录不符合当前筛选，提示已保存及筛选影响；若保存后刷新查询失败，区分“保存成功”和“读取失败”。请求中途断开导致结果不确定时提醒刷新核对，不自动重试新增。

快速切换筛选时取消旧请求或忽略过期响应。列表与统计刷新任一失败时明确标注未同步，不能把不同筛选条件的结果拼接显示。

## 数据规则

字段、格式、日期边界、错误响应及统计口径以 [API_CONTRACT.md](API_CONTRACT.md) 为准；表结构以 [DB_DESIGN.md](DB_DESIGN.md) 和 [schema.sql](../database/schema.sql) 为准。

单笔金额范围 `0.01`～`99999999.99`，币种固定 CNY。类型仅 `income` / `expense`。备注可为空，最多 500 字符。日期不限制为过去时间，但必须是合法日期且在 MySQL DATE 范围内。结余为收入减支出，统计金额可能大于单笔金额上限。

## 范围与运行边界

不做登录、多人账本、预算、转账、多币种、导入导出和线上部署。前后端仅作为本地 Demo 运行，数据库为用户部署的共享 `mysql8` 服务。应用使用独立数据库 `finance_demo`，清理项目不删除共享容器、命名卷和数据库数据。

## 核心验收场景

在 `finance_demo` 的干净验收基线下，通过页面添加收入 `1000.00`（工资）和支出 `125.50`（餐饮），日期均为 `2026-11-15`。SQL 验证两条记录及字段，页面显示收入 `1000.00`、支出 `125.50`、结余 `874.50`。刷新页面后仍一致。

若数据库已有用户记录，不清空数据：先记录数量和统计基线，再按两笔记录的 ID 验证数量增 2、收入增 `1000.00`、支出增 `125.50`、结余增 `874.50`。测试只能删除明确由测试创建的记录。
