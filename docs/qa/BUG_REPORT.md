## QA-P0-001：写入 5xx 后可能误导用户立即重试

- 来源：主 Agent 的代码审查发现，非 QA 先前端到端复现。
- 所属模块：前端请求错误归一化与提交状态，严重程度：可能重复记账的风险。
- 触发条件：POST 在后端提交后确认链路失败，前端收到 HTTP 500 / 503。原逻辑仅把“没有响应”的网络失败标记为结果不确定。
- 期望：保留输入，提示结果尚未确认，锁定提交，要求成功读取后核对，不自动重试 POST。
- 根因：不能从 HTTP 5xx 推断数据库一定没有提交，写入操作的结果与响应送达是两个事件。
- 分派与修复：主 Agent 分派 frontend-developer，现将写入 5xx / 网络失败统一标记 uncertain，失败刷新保留锁，成功刷新提示核对明细。
- QA 复测：`node tests/client_error_unit.mjs` 验证实际错误函数的 500 / 503 / 网络分支；`node tests/browser_p0_smoke.mjs` 在真实 POST 503 下验证保留表单、锁定、失败刷新不解锁及不重发。
- 状态：已修复，独立单元和实际 503 分支复测通过；真实“已提交但响应失败”的数据库链路故障注入未执行，不虚构该场景的端到端证据。
